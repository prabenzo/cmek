## Overview

**What this milestone accomplishes.**

- The invariant panel goes live, judged from outside the service's trust boundary. Once a second a checker re-verifies S1–S4 from evidence the service does not write: a scan of the stored rows for the plaintext canary (S1), the sink's count of deliveries whose payload named another tenant (S2), the fake KMS's ground-truth revoke time against the sink's delivery timestamps, with the window closing at the ground-truth restore so a draining backlog is never counted (S3), and a per-tenant census taken in one consistent snapshot proving accepted = delivered + queued + expired + dead, bounded by the sink's independent count (S4). The page's lights turn green, or red, with no web change.
- The checker is falsifiable: a unit test drives it against fakes and proves each light turns red on a violation, and a local script runs all six scripted scenarios in turn (the five cards' six Start buttons; blip and outage share a card) against one open stream and fails on a dead stream, a silent checker or any red light, so "panel green through every scenario" is a verdict rather than an absence of reports.
- The World lifecycle becomes real: the Reset button and endpoint rebuild the World under a new id and the page reconnects; a stream arriving after more than 10 s with no viewers gets a fresh World, so a reviewer never opens someone else's leftover outage; handlers are refcounted so a rebuild never closes the database under a request in flight.
- Queue housekeeping the spec promised: messages claimed by a worker that went silent are reclaimed (at-least-once delivery), and parked messages past retention expire, both wired into the sweep.
- The second revocation timeline line, "revoked at … (ground truth), detected in x s": the only line that reads ground truth, and the pair with the service's own line is what makes "detected" falsifiable.
- The final deploy from Ben's laptop, a short README (thesis, live URL, how to run, deploy recipe, links) and a clean-browser smoke test on the live URL: first snapshot within seconds of a cold start, lights green, Reset increments the world id, a tab closed for 11 s gets a fresh World.
- Deliberately not yet done: the expected cut is the L1 and L4 lights, decided at the start of the box from the time log (the panel then ships with four lights and L1/L4 move to the buffer window); stream hardening (a per-frame write deadline, a 55-minute stream age with reconnect) gives way first if the deploy minute arrives, and the fast-fail storm test, the holder idle-rule test and M2's walk extras are buffer items (the idle-rule test enters the box only if the checker test is green by 3:36).

Refcount note (a precision on ARCH › World › Lifecycle, which sketches `inflight` on the Holder): the WaitGroup is **per World**. `Reset` runs `old.Stop(); new = New(); new.Start()` under `holder.mu`, so no viewer of the new World can `Acquire` before it returns; the reason for per-World scope is that a handler outliving `StopTimeout` on an old World (logged, not waited) would, with a Holder-wide group, make every later rebuild wait the full `StopTimeout` again. `Stop` order: cancel ctx → `metrics.CloseAll()` (SSE loops see `!ok`, return, `release`) → wait ≤ `StopTimeout` on `wg` and `handlers` via `clock.After` → log any late goroutine → `store.Close()` → remove the three DB files. The reset handler does **not** go through `Ensure`: holding a `release` while calling `Reset` deadlocks by construction.
